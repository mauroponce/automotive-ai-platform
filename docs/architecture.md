# Architecture

The product has exactly two modes.

1. **Free browser plate blur:** shared `components/free-tools/plate-editor.tsx`, extracted from the existing landing editor. The browser loads the specialized ONNX model from `/models/` and ONNX Runtime Web/WASM from `/ort/`. Editable suggestions, manual regions, zoom/pan, Canvas blur and local downloads require no authentication, remote photo storage, processing endpoint or credits. A missed detection must be corrected by the user. Weight licensing remains blocked; see [provenance](browser-detector-license.md).
2. **Advanced OpenAI editing:** authenticated dealership uploads are decoded, oriented and validated using Sharp, then stored privately in S3. A persistent Prisma batch contains 1–15 source images, a platform/dealership showroom snapshot, per-image prompt snapshots and a versioned tariff reference. No local server vision or composition engine exists. OpenAI performs backgrounds, lighting, integration and shadows. Sharp only performs auxiliary image validation/conversion.

Google OAuth verifies email before account linking. Registration creates an owner membership and an exact 14-day trial. Server authorization reloads roles and memberships; trials do not authorize paid inference. Batch creation atomically reserves a manually provisioned organization allowance. Dispatch also requires explicit server spend authorization. Credits and verified payments remain future work.

Tenant Prisma transactions set `app.current_organization_id`. Forced PostgreSQL RLS protects assets, batches/items, entitlements and generation records using the non-superuser `automotive_app` role. The server-only owner URL remains necessary for trusted cross-tenant worker lookups and authentication registration operations; it is never a client credential. Runtime queue access does not create schemas. Only the migrator performs queue DDL and grants.

Batch queuing and state transition share a PostgreSQL transaction via pg-boss's database adapter. Submission is claimed durably before any provider request. An uncertain submission cannot automatically be sent again: reconcile its provider metadata and grant/recover manually. Reconciliation handles output/error files, partial failures, missing items and duplicate delivery without charging or storing twice. Provider results stay unverified until review. Downloads require current organization membership/trial access; simulated results carry explicit metadata and UI labels.

The injectable Batch provider exists for deterministic tests; no environment switch exposes a fake provider to customers. Production uses OpenAI Batch `/v1/images/edits`, JSON `images` references and private presigned S3 URLs. Versioned token estimates are distinct from invoiced costs. Missing usage stays unknown and requires reconciliation.

Docker has separate web, worker and migrator targets. Web uses standalone Next.js; worker retains all production dependencies including Prisma and Sharp; migrator installs from the repository lockfile. PostgreSQL stays private, and Caddy handles HTTPS. Historical laboratory tables and migrations remain intact without active consumers; see [data retirement proposal](data-model.md).
